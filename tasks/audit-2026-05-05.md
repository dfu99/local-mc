## §3 · The single biggest blocker

**Verified `ClaudeAgent` turn against the real `claude` CLI — and that the
combination of flags `claude -p --output-format stream-json --input-format
stream-json --verbose --resume <sid>` actually exists and emits the events
that `_parse_event` decodes.**

Why this is *the* blocker, not just one of several:

- It's the only feature in v0.1 that has *zero coverage* (echo, sandbox,
  uploads, websocket, sqlite all proved working).
- Every downstream feature (status panel, AFK queue, batch, reports,
  per-project objective preview) depends on the agent path working.
- The lesson at `lessons.md:11` already flags this. We can't keep adding
  features behind an unverified turn.

Why it hasn't been resolved: the scaffold was authored on this machine
without touching the real `claude` CLI; the lesson was written *while*
guessing the flags. The fix needs (a) a real `claude` install, (b) one
written turn, (c) inspection of the actual JSON event stream against the
parser. That has not happened in the 28 commits between `88b1d0b` (init)
and `2f73cc3` (scaffold) — there are only those 2 commits.

## §4 · Drop list

- **`watchfiles>=0.21` dependency.** Never imported. Either delete it from
  `pyproject.toml` and `requirements.txt`, or actually use it for live file
  watching. Until then it's audit-surface for IT review with no benefit.
- **The `package-data = lmc = ["../web/**/*"]` pattern.** It works on Linux
  but is sketchy enough that Windows wheel builds may diverge. Replace
  with a `MANIFEST.in` `recursive-include web/` (or move web/ inside the
  package as `lmc/web/`). One-line change; removes a footgun.
- **`Settings.artifact_globs`.** Currently dead. Either thread the field
  through `server.py:_run_turn` so users can override discovery globs, or
  delete the field. Right now it's documented config that does nothing.

## §8 · Brittleness pass — what's likely to break first

(written without re-running the smoke test — based on code reading)

1. **`ClaudeAgent._parse_event` silent skips.** `kind` other than the four
   handled values are silently dropped. If Claude Code introduces a new
   event type the user will see a black-hole turn with no logs. Add a
   trace-level log of unhandled `kind`s.
2. **`ClaudeAgent.stream` stdin close.** Uses sync `proc.stdin.close()`
   not `await proc.stdin.wait_closed()`. On Linux this is fine; on
   Windows asyncio's proactor loop has bitten people with
   non-await-closed transports.
3. **`Store.append_to_message` is a SQL UPDATE per delta.** That's one
   sqlite write per token. Fine at 50 tokens/turn but not at 5,000. Batch
   into a buffer + periodic flush in v0.2 if it's measurably slow.
4. **WebSocket exception path.** `except Exception as e` at
   `server.py:384` swallows any error then tries to send via the same
   socket; if the socket is already closed the second send raises
   silently. Consider logging then closing.
5. **Settings YAML has no validation.** Bad keys are silently ignored
   (`load_settings` filters by dataclass field names). User typo →
   feature silently disabled.
6. **`_safe_filename` truncation.** `cleaned` is sliced to 200 chars,
   then prefixed with `<ts>-<uuid6>-`, which can produce 220+ chars.
   On NTFS the per-component limit is 255 — close to the line.
7. **Artifact diff snapshots only on user-message receipt.** If the agent
   wrote files asynchronously *between* turns, they'll be reported as
   artifacts of the *next* turn. Cosmetic, but confusing.
