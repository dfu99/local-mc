# Cron schedule — 24h sprint window beginning 2026-05-05 01:30

User asked for "frequent triggers" to ensure the project gets fleshed out
over the next 24h. Implementation: a `/loop` schedule that wakes the
agent every ~30 minutes for 24 hours, pulling the next item from
`tasks/queue.yaml`.

## Schedule

- **Cadence:** wake every 30 minutes (long enough that prompt-cache is a
  wash, short enough that 24h gives ~48 ticks).
- **Window:** 2026-05-05 01:30 → 2026-05-06 01:30 local.
- **What each tick does:**
  1. Read `tasks/queue.yaml`.
  2. Pick the first item where `status: pending` and dependencies satisfied.
  3. Execute it (write code / tests / scripts as needed).
  4. Run any tests that exist.
  5. If green, mark item `status: completed` and append objective to
     `tasks/objectives.yaml` with a fresh figure.
  6. Commit with a clear message; do not push without user permission.
  7. If queue is empty: extend it with §9 of `tasks/audit-2026-05-05.md`,
     or stop and post a Slack summary.

## Stop conditions

- All queue items completed.
- Hit a P0 blocker requiring human input — surface via Slack and stop.
- 24h elapsed.
